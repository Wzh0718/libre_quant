## 一、方法论（用户提出的方案）

> "用历史外加上影子去测试，如果没有问题则进行替换学习"

即 **champion–challenger / shadow mode**：

1. **历史回测**只是海选（docs/04~09 已完成）；
2. 新策略先上**影子盘**：与现役策略并行跑真数据、真时间，不碰真钱；
3. **晋升标准事先写死**，达标才替换（challenger → champion）；
4. 不达标则枪毙，现役策略不受任何影响。

当前 champion = 规则栈（每日定投 200 + 溢价>5% 闸门，docs/09）；
影子盘两臂并行：**gate 臂**（champion 本体的影子复刻）vs
**naive 臂**（无脑日投对照）。未来的 ML/自适应 challenger 直接进同一框架，
与 champion 用同一套检查单比。

## 二、实现

* 每日 20:00 `serve.py` 采集完成后自动 `shadow.run_daily`：
  读最新价/溢价 → 闸门判定 → 两臂各走一步 → upsert（幂等，同日重跑安全，
  状态从 `day < T` 重放）。
* 成交价代理 = 当日不复权收盘（≈14:50 收盘前执行）；
  佣金 = 配置口径（万 0.5 / 最低 0.1 元）。
* `uv run python scripts/shadow.py --report`：两臂对比 + 晋升检查单。

## 三、晋升标准（事先写死，改动必须记录在此节）

| # | 标准 | 说明 |
|---|---|---|
| 1 | 影子运行 ≥ 60 个交易日 | ~3 个月，覆盖至少一次溢价 regime 切换的概率较高 |
| 2 | 信号日志无缺口 | 数据管道 ops 验证（每日 20:00 任务可靠） |
| 3 | gate 臂买入平均溢价 < naive 臂 ≥ 2pp | 闸门确实买在了更便宜的位置 |
| 4 | 期末 XIRR 复核：gate 臂 ≥ naive 臂 − 1pp | 短期噪声容忍，≥60 日后才判定 |

## 四、诚实边界

1. 影子盘对**规则**的主要价值是 ops 验证（数据管道、闸门触发、执行口径），
   统计证据回测已经给了；它的真正主场是未来的**自适应/ML challenger**
   （那种东西的回测可信度天然存疑，必须先跑影子）。
2. 60 天只覆盖一种市场环境；若期间溢价全程 >5%，gate 臂全程空仓，
   标准 3 无法判定——届时顺延而非放宽。
3. 成交价用收盘价代理，未建模 14:50 实盘的微小价差；对日频策略影响 <0.1%。
