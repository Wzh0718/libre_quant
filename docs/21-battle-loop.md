# 21 · 作战闭环（2026-09-16 重构主线）

> 本文档是当前产品形态的权威说明。用户初衷五步闭环：
> **① 选标的拉全量数据 → ② 策略跑历史复盘调参 → ③ 生成未来一周作战方案
> （什么价位买多少/卖多少）→ ④ 录入实际成交，计划 vs 实际反哺策略 →
> ⑤ 策略版本管理与迭代。**

## 为什么重构

旧形态是研究驱动：20 篇文档 + 6 个看板页，核心结论「日线方向预测无 alpha」
被当成了**拒绝给操作方案**的理由 —— 这违背了用户初衷。重构后：

* 研究资产（PCF 归因、美股领先性、QDII 溢价等）降级为数据层能力，
  旧页面（/today /analysis /replay /shadow）保留路由但退出主导航；
* 主导航收敛为四页：**作战台 / 复盘 / 我的盘 / 策略库**。

## ③ 的核心设计：规则触发单，不是价格预测

用户规则是「近 7 日涨跌幅超过阈值就多买/卖出」（workbench 口径）。
**未来 ≤7 个交易日的「7 日前参考价」全部是已知历史收盘价** ——
所以触发条件可以写成精确价格：

```
收盘 ≤ 0.6509 → 买入 600 元 ≈ 922 份      （多买档：ref × (1-3%)）
收盘 ≥ 0.7381 → 卖出 1250 份 ≈ 923 元     （卖出档：ref × (1+10%)，按真实持仓算份数）
否则          → 基准买入 200 元
溢价 > 5%     → 当天什么都不做（优先级最高）
```

诚实性边界（`battle.weekly_plan` 的 disclaimer）：
方案不含价格方向预测；触发价由已知参考价精确算出，
与回测引擎（`workbench.run_history`）**同一判定口径** ——
方案头部附的「这套规则跑全程历史」就是同参数回测结果。

### 复权口径（515880 的教训）

515880 在 2026-02-03 / 2026-07-06 两次份额折算（raw -65.7%/-52.1%，
adj +2.8%/-4.2%）。因此：

* **规则判定在复权空间**（与 run_history 一致），触发价再按当前折算因子
  换算回不复权口径（用户挂单位用的是不复权价）；
* **态势的涨跌幅/波动率/回撤也用复权**（否则 515880 的波动率被假暴跌
  吹到 161%，真实 66%）；均线值 × 当前因子换算回不复权口径便于对照。

## ④ 计划 vs 实际（`battle.plan_vs_actual`）

作战台「落盘为本周方案」把方案存进 `battle_plan` 表（绑定实际盘）。
日子过去后，我的盘 →「计划 vs 实际」逐日对照：

* 计划动作（买入/多买/卖出/暂停）× 真实收盘 × 真实成交 →
  一致 / 未执行 / 偏离 / 未到；
* 执行一致率 + **参数反哺建议**：
  * 多买档从未触发且实际最深回踩远浅于档位 → 建议收紧 `dip_drop`；
  * 一致率 <60% → 提醒执行纪律（条件单挂券商）；
  * 闸门日/无触发日规则外买入 → 追高提示。

## ⑤ 策略库（`strategy` 表）

参数快照 + `parent_id` 血缘（"这版是基于哪版改的"）。
复盘页调参 → 跑历史 → 存版本 → 勾选对比（同标的同口径并排指标+曲线）。
作战台可按版本生成方案。

## API 一览

| 端点 | 用途 |
|---|---|
| `GET /api/battle` | 作战方案（strategy_id / 内联参数 / user_plan 兜底） |
| `POST /api/battle/save` | 方案落盘（绑实际盘） |
| `GET /api/battle/tracking` | 计划 vs 实际 + 反哺建议 |
| `POST /api/review/run` | 任意参数跑全历史（不落盘） |
| `GET/POST/DELETE /api/strategies` | 策略版本 CRUD |
| `POST /api/strategies/compare` | 多版本同口径对比 |
