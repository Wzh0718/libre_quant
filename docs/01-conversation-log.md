# 对话记录：从「同花顺数据 + 无法自动下单」到 libre_quant

> **日期**：2026-09-11
> **参与者**：用户（libre）/ AI 助手（DSH）
> **性质**：结构化纪要，非逐字转录。保留决策依据、被否决的方案、以及实测数据。

---

## 0. 起点问题

> 「我如果想做量化，现在只能拿到同花顺的数据，但是做不了自动下单，这个要如何解决？」

**拆解出的两个独立问题：**

| | 状态 | 症结 |
|---|---|---|
| 数据 | 同花顺（客户端 / 问财 / 可能 iFinD） | 同花顺是数据资讯商，**不提供零售交易 API** |
| 下单 | 只能手点 | 散户下单通道只由**券商**提供 |

**结论**：这不是"如何自动化同花顺"的问题，而是"去开一个有官方量化通道的券商账户"。

---

## 1. 第一轮方案对比（四条路线）

| 路线 | 方式 | 门槛/成本 | 风险 |
|---|---|---|---|
| **A. 券商官方量化通道** | QMT / miniQMT / PTrade + `xtquant` | 各家不同，几万~50万 | 最低 |
| **B. 同花顺 SuperMind** | 官方在线量化平台（原 MindGo） | 平台内确认 | 低，但策略跑在别人服务器 |
| **C. UI 自动化** | `easytrader` + 同花顺客户端 | 需 Windows，先手动登录 | 高，客户端升级即崩；多数券商协议禁止 |
| **D. 期货 CTP** | vnpy / openctp | 几万起 | 低 |

**同轮提出的关键工程建议**：数据层与执行层解耦，执行层可替换（人工 → xtquant）。

## 2. ⚠️ 关键转折：miniQMT 正在被关闭

**这一条推翻了第 1 轮的推荐 A。**

| 时间 | 事件 |
|---|---|
| 2026-07-06 | 部分券商新开 QMT 权限**不再包含 MiniQMT** |
| 2026-08-21 | **国金证券下发通知**，确认 MiniQMT 关闭，存量客户也无法使用 |

**原因**：MiniQMT 用本地原生 Python 直连 `xtquant`，易被认定为"**外接系统**"，触碰合规红线。

- **MiniQMT（被收紧）** = 本地 Python + xtquant，脱离客户端运行 ❌
- **大 QMT 主程序（不受影响）** = 内置 Python，跑在客户端沙箱内 ✅

**合规背景**：证监会 2024-05-15《证券市场程序化交易管理规定（试行）》；
沪深北交易所《程序化交易管理实施细则》**2025-07-07 施行**（[上交所规则页](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml)）。
高频认定：单账户每秒申报+撤单 ≥300 笔，或全日 ≥20000 笔（散户低频策略碰不到）。

## 3. 用户澄清的真实方案

> 「资金只够做一只股票，偏向 ETF 或其他，做复利。相当于做 agent 策略分析，
> 生成对应的条件单，做可视化和日线，比如在哪个点买入、挂什么单，后续只需要开长线卖出。」

**当时指出的四个问题：**

1. **技术投入与策略需求错配** —— 计划做秒级 hook，但策略是日线级别
2. **漏了 ETF 最关键的指标：溢价率** —— 跨境 ETF 常溢价 3%~10%，在溢价 8% 买入等于开局先亏 8%
3. **Agent 该坐副驾驶，不该当驾驶员** —— 不可回测、不可复现、不可归因的判断不能当策略
4. **"长线卖出"是最大风险** —— 买入是一次性决策，卖出才是持续决策；且条件单通常**当日有效**

## 4. 用户澄清：要的是「PCF 实际持仓明细」

> 「并不是哦，我们需要分析该股票对应的持仓明细，你能理解吗？」

**AI 此前的错误**：建议用**指数成分股权重**做主表。

**纠正后**：要用**基金实际持仓明细（PCF）**——

| | 指数成分权重（错） | PCF 持仓明细（对） |
|---|---|---|
| 数据 | 百分比 | **持股数量** |
| 来源 | 指数公司 | **申赎清单 / 定期报告** |
| 本质 | 理论应持有**什么** | 实际持有**多少股** |

**为什么这个区别是实质性的**：
1. ETF 有抽样复制、现金留存、打新、融券，**指数权重 ≠ 实际持仓**
2. 只有持仓明细带**数量** → 能算精确市值贡献、能看调仓动作、能算申赎资金流
3. 用指数权重做归因只是**估算**

## 5. ✅ P0 Spike：PCF 通路验证成功

**验证目标**：能不能稳定拿到 515880 的每日 PCF？能不能拿到历史？

### 结果（超出预期）

```
https://m.gtfund.com/cochin/etf/download/515880/{yyyymmdd}
```

- **404 = 非交易日**（不是错误）
- 站点 CDN 有 cookie 挑战（`Ws-Action: cc` + 5 分钟 `C3VK`），`requests.Session` 自动处理
- **无登录、无签名、无加密参数** —— 比逆向同花顺简单几个数量级

| 日期 | 结果 |
|---|---|
| 2019-12-02（成立后） | ✅ 57 只 |
| 2020-08-18 | ✅ 59 只 |
| 2023-01-04 | ✅ 50 只 |
| 2026-09-09/10/11 | ✅ 50 只 |

**7/7 全中，0 失败。历史完整，能回测。**

### 两代格式（都已支持）

| 时期 | 格式 | 编码 |
|---|---|---|
| ~2025-11 及以前 | INI 头 + `TAGTAG` + 竖线分隔 | **GBK** |
| 2025-12 起 | `<SSEPortfolioCompositionFile>` XML | UTF-8 |

### ⚠️ 发现的陷阱：现金替代占位腿

**`RecordNumber=50`，但基金实际只持有 43 只。**

其余 7 只是"**必须现金替代**"占位腿（`flag=2` + `quantity=0`）：
`300913 兆龙互连`、`301205 联特科技`、`301678 新恒汇`、`688027 国盾量子`、
`688182 灿勤科技`、`688205 德科立`、`688668 鼎通科技`

标志语义（三组互斥，与市场完全吻合）：

| 分组 | 数量 | 含义 |
|---|---|---|
| `flag=1` + 有数量 + **无** cash（16只） | 全沪市 | 禁止现金替代，实物交付 |
| `flag=1` + 有数量 + 有 cash（27只） | 全深市 | 可以现金替代 |
| `flag=2` + **数量=0**（7只） | 混合 | **基金未持有，必须剔除** |

`UnderlyingSecurityID`：`101`=沪市、`102`=深市。

**不剔除这 7 只，权重就算错。** AI 第一版代码正是掉进这个坑，
一度误判"工业富联不在篮内"。

## 6. 话题转向：因素太少 & 秒级标的

> 「其实我们应该探讨的是关于如何调整策略。因为现在我们考虑的因素太少了，
> 然后股票又是那种秒级别的。」

**当时的核心重构：**

### 6.1 秒级数据不该进决策层

用户的执行是分钟级（人工/条件单），秒级信号**用不了**。但它该放在**状态层**：

| 层 | 频率 | 回答的问题 |
|---|---|---|
| 背景 | 季/月 | 要不要在场 |
| 趋势 | 日/周 | 方向 |
| **状态** | **秒/分** | **今天能不能动手** ← 秒级在这 |
| 执行 | 分钟 | 挂什么单 |

### 6.2 提出的因素清单

- **趋势层**：相对强度 RS、隔夜美股映射、均线结构
- **状态层**：宽度、龙头分化度、资金集中度、溢价率
- **资金层**：ETF 份额变化、融资融券
- **仓位层**：ATR / 已实现波动 → **波动率倒数定仓**

### 6.3 关于"怎么调"的警告

单标的、43 只成分股、2019-12 至今 ≈ **6 年 / ~1500 根日线**。

> **在这个样本上精调参数，几乎必然过拟合。这不是保守，是数学。**

正确顺序：**建记录 → 建归因 → 单因子检验 → 只在证据充分时改**。
没有第一步，调的每个参数都是猜。

## 7. ❌ 实证否决：隔夜美股映射没有可交易价值

AI 曾主张「隔夜美股（COHR/LITE/AAOI/NVDA）是这个标的最该补的领先指标」。
**用户要求验证，结果否掉了这个假设。**

### 检验设计（关键）

美股日 D 收盘 = 北京时间 D+1 凌晨 04:00，A 股 D+1 于 09:30 开盘。
所以「US_ret[D] 与 A_ret[D+1] 相关」几乎是必然的 —— **信息在集合竞价就已反映**。

真正可交易的问题是：

```
gap[T]   = A_open[T] / A_close[T-1] - 1     ← 信息传导到开盘（无交易价值）
intra[T] = A_close[T] / A_open[T] - 1       ← 开盘后是否延续（这才可交易）
```

### 结果

| 标的 | n | r(US, **gap**) | r(US, **intra**) |
|---|---:|---:|---:|
| TSM | 639 | **0.453** | 0.004 |
| LITE | 639 | 0.411 | 0.024 |
| COHR | 639 | 0.398 | 0.028 |
| MRVL | 639 | 0.344 | 0.023 |
| NVDA | 639 | 0.293 | **-0.047** |
| AAOI | 639 | 0.286 | 0.051 |
| AVGO | 639 | 0.252 | 0.001 |
| 光模块组等权 | 639 | 0.401 | 0.044 |
| 新易盛 | 639 | 0.382 | 0.015 |
| 中际旭创 | 639 | 0.368 | 0.021 |

多 horizon 复核（1/3/5/10/20 日）：**全部 ≈ 0**（-0.04 ~ 0.05）。

**结论**：美股信息**强传导到开盘（r≈0.4）**，但**开盘后完全定价，零 alpha**。

### 这个否定结果的含金量

> 如果连 **COHR / LITE**（业务直接对标、时间明确领先、gap 相关性 0.4）
> 都预测不了 A 股后续走势 —— 那么**"用公开信息预测这个标的的日线收益"这条路基本是关的**。

并且**印证了用户的直觉**："股票是秒级别的" ——
**alpha 大概率在秒级，而秒级正是数据能力和执行能力都够不到的地方。**

**决策：不要在这个标的上做日内。**

## 8. Tavily 检索能力验证

### 诊断

DSH 的 `web-search-deepseek` 插件配置 `baseURL: https://tavily.ivanli.cc/mcp`，
插件会拼成 `/mcp/messages` 去调 **Anthropic 兼容 Messages API** —— 但该主机**只提供 MCP 协议**。
**协议不匹配，改 URL 治不好。**

| 探测 | 结果 |
|---|---|
| `/v1/messages`、`/messages` | ❌ 404 |
| `/sse`、`/mcp/sse` | ❌ 404 |
| **`POST /mcp`** | ✅ **唯一正确入口** |

### 验证通过

- Token 有效，服务器 `tavily-mcp v0.2.0`
- 工具：`tavily_search` / `tavily_extract` / `tavily_crawl` / `tavily_map` / `tavily_research`
- 实跑检索成功

### ⚠️ 硬限制：Tavily 无法回测

**检索是"当下"的，拿不到历史新闻快照。** 搜索引擎返回当前索引，
无法可靠取回"2024 年 3 月那天的新闻"。

→ 只能从今天开始每天落盘，积累 3~6 个月后才能检验。

**定位**：事件风险预警 / 背景判断 / 归因解释 —— **不是预测收益**。

## 9. 沉淀出的方法论

本次对话最有价值的产出不是代码，是这套**筛子**：

> **任何候选因素，先过 gap/intra 分离 + 多 horizon 检验。
> r(intra) 与 r(多日) 双双 ≈ 0 的，直接淘汰。**

这样调策略时淘汰是**有证据**的，而不是在回测里试出来的（那个必然过拟合）。
