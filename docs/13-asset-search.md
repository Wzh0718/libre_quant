# 标的检索层：输入代码 → 拉历史 → 跑盘（docs/13）

> **日期**：2026-09-15 · **代码**：`libre_quant/universe.py`（分类）·
> `libre_quant/data/discover.py`（探测）· `scripts/ingest.py`（`ingest_one`）
> · API：`/api/resolve` `/api/ingest` `/api/assets` · 前端顶栏「标的检索」
> 起因：用户要求「用户可以填写基金或者是股票号，然后进行检索历史数据，之后再跑盘」。

## 一、为什么要做这一层

原先把标的写死在 `UNIVERSE` 注册表里（4 只 ETF + 2 只美股）。一旦要研究
任意基金/股票，就需要：**识别类别 → 找对数据通路 → 入库 → 之后所有分析页自动可用**。

## 二、代码冲突：分类不能只看前缀

A 股代码存在**基金与股票重号**：`000001` 既是「平安银行」也是「华夏成长」。
所以分类分两步：

1. **纯函数形态判定**（`classify_code`，可离线测）：

| 形态 | 市场 | 类别 | 数据通路 |
|---|---|---|---|
| `5xxxxx` / `1xxxxx` | sh / sz | 场内基金（ETF/LOF） | 腾讯行情 + 东财净值 + 溢价 |
| `6xxxxx` / `0xxxxx` / `3xxxxx` | sh / sz | 个股（**也可能是场外基金**） | 腾讯行情（无净值） |
| `4xxxxx` / `8xxxxx` | bj | 北交所个股 | 腾讯行情 |
| `2xxxxx` / `9xxxxx` / 其他 | otc | **场外基金** | 仅东财净值（无场内价格） |
| 字母 / 带点 | us | 美股 ETF/个股 | 新浪美股日线 |

2. **探测裁决**（`discover`，联网）：先试场内快照；拿不到但净值存在 →
   判为场外基金（这就正确处理了 `000001` 的重号：有行情→股票）。

**QDII 判定**用**基金全名**做关键词匹配（`纳指/标普/恒生/QDII/海外…`，
取自东财 `fS_name`），命中即 `lag=2`（保守净值滞后）。
实测：`270042 → 「广发纳斯达克100ETF联接人民币(QDII)A」` → 自动判为 QDII ✓。

## 三、跑盘通路：价格优先，净值兜底

`store.load_series(code)` 统一加载序列：

* 有场内价格 → `(days, 不复权, 前复权, "price")`
* 无价格有净值（场外基金）→ `(days, nav, nav, "nav")`
* 都没有 → 空（提示"请先检索入库"）

`/api/today`、`/api/analysis`、`/api/replay`、`/api/review`、`/api/decomp`
全部改用 `load_series`，因此**股票、场外基金、美股都能直接跑盘**；
无净值数据的标的自动跳过溢价闸门（溢价表为空 → 闸门恒通过）。

## 四、API 与前端

| 端点 | 作用 |
|---|---|
| `GET /api/resolve?code=` | 探测：名称/类别/市场/价格与净值覆盖/是否已在库（**不写库**） |
| `POST /api/ingest?code=` | 拉取并入库（幂等）：价格 + 净值 + 溢价 + 名称元数据 |
| `GET /api/assets` | 库中所有标的清单（含检索入库的，名称来自 `asset_meta`） |

前端顶栏新增**「标的检索」**输入框：输入代码 → 探测 → 未入库则自动拉取 →
刷新标的清单并切换过去；页面顶部显示名称/类别/覆盖区间/提示。
`asset_meta` 表保存注册表外标的的名称与类别，供 `/api/assets` 与页面标题使用。

## 六、局限

1. **场外基金无溢价、无日内价格**：只能用净值跑盘与定投复盘；
   申赎费率（C 类销售服务费/赎回费）未建模，实际收益会低于本文数字。
2. **股票无净值**：溢价闸门自动失效，只有价格类分析（回撤/波动/定投复盘）。
3. QDII 判定依赖名称关键词，可能漏判（如名称不含关键词的海外基金）；
   命中后会按 lag=2 保守处理，未命中按 lag=1（更激进，理论上可能高估）。
4. 库中标的会持续累积（`/api/assets` 会变长），暂未做归档/清理；
   前端选择框在标的很多时需要搜索（目前用 datalist 兜着）。
